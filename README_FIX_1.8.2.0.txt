■ ۱) سربازخانه‌ی اتحادیه — چه چیزی خراب بود و چه شد
  مشکلاتِ گزارش‌شده:
    • «منوی کشویی»: همه‌ی ۱۷ واحد در یک لیستِ مسطحِ ۵تایی بود (خرید و ارتقا قاطی هم).
    • بعد از هر خرید، منو به صفحه‌ی اول برمی‌گشت (alw:prod:0 هاردکد شده بود).
    • هر کلیک فقط «یک» اسکادران می‌ساخت و تعداد از کاربر پرسیده نمی‌شد.
    • صفِ تولید نه صفحه‌ی مدیریت داشت، نه لغو/بازگشتِ هزینه؛ حسِ «فقط یک صف ساخته می‌شود».

  ساختارِ جدید (دقیقاً مثلِ بخشِ نظامیِ عادی):
    🏰 سربازخانه (alw:bk)
      ├─ 🏭 تولید نیرو (alw:shop)  → ۷ دسته‌ی مستقل (پیاده/تسلیحات/زرهی/پدافند/موشکی/جنگنده/بمب‌افکن)
      │     └─ alw:cat:<cat>  → نیروهای همان دسته با آمار، قیمتِ اسکادران، زمانِ ساخت، مزایا/معایب
      │           └─ alw:buy:<unit>  → «چند اسکادران؟» با دکمه‌های ۱/۲/۵/۱۰ + «حداکثر طبق ظرفیت و صندوق» + ⌨️ تعدادِ دستی
      │                 └─ alw:buyq:<unit>:<n>  → پیش‌نمایش (هزینه/ظرفیت/زمان) → alw:buyok:<unit>:<n> → ساخت
      │                       ↳ پس از ساخت به «همان دسته» برمی‌گردی، نه صفحه‌ی اول ✅
      ├─ 🏗️ صفِ تولید (alw:queue:<page>) → پیمایشِ واقعی ۶تایی + به‌روزرسانی
      │     └─ 🗑️ لغو با بازگشتِ کاملِ هزینه به صندوق (alw:qcancelmenu / alw:qcancel:<id>)
      ├─ 🎖️ ارتقا و آموزشِ مستقل (alw:upgm) — کمبودِ صندوق = 🔒 روی دکمه
      ├─ ⬆️ ارتقای سربازخانه (alw:upbk) و 🤖 تولید خودکار (alw:auto) — بدونِ تغییر
      └─ 🏥 بیمارستان و 📖 راهنما — بدونِ تغییر

  نکات:
    • ساختِ چند بچ پشت‌سرِ هم آزاد است؛ هر بچ یک ردیفِ مستقل در صف می‌گیرد و
      ظرفیتِ خالی همیشه با احتسابِ صف محاسبه می‌شود (مثلِ mil:queue).
    • callbackهای قدیمی سالم‌اند: alw:prod:* به فروشگاهِ جدید هدایت می‌شود و
      alw:buy:<unit> به‌جای خریدِ فوری، منوی انتخابِ تعداد را باز می‌کند (امن‌تر).
    • «حداکثرِ قابلِ ساخت» = min(ظرفیتِ خالی ÷ اندازه‌ی اسکادران، صندوق ÷ هزینه‌ی اسکادران)
      در app/data/alliance_military.py::max_squads_possible

  🐞 دو باگِ پنهان که حینِ بازبینی پیدا و رفع شدند:
    • alw:autoset:* (تنظیمِ حداقلِ تولید خودکار) به‌خاطرِ startswith("alw:auto")
      هرگز به هندلرِ خودش نمی‌رسید و در منوی auto گیر می‌کرد → فیلتر به «alw:auto:» شد.
    • alw:war (نبردِ زنده) با F.data == "alw:war" مقایسه می‌شد، ولی دکمه‌ها پسوندِ
      مالک دارند (alw:war:<uid>) → دکمه همیشه مرده بود → به startswith تغییر کرد.


■ ۲) سیستمِ لاگینگ با جزئیاتِ کامل
  فایل‌های جدید:
    app/utils/logging_setup.py        ← نصبِ هندلرها (idempotent؛ با GodFATHER_LOG_DIR قابلِ تغییر)
    app/middlewares/update_logging.py ← ردِ کاملِ آپدیت‌ها + ثبتِ خطاها با متنِ کامل

  خروجی در پوشه‌ی logs/ (خودکار ساخته می‌شود؛ گردش‌پذیر ۵MB):
    bot.log      ← همه‌ی رویدادها (INFO+) — روایتِ زمانیِ کامل
    errors.log   ← فقط خطاها + traceback کامل + متنِ آپدیت (چه کسی/چه دیتایی/چه استیتی)
    updates.log  ← ردِ هر پیام و کلیک: «⬅️ شروع» و «➡️ پایان (مدت)» با کاربر و callback_data

  مثالِ خط در updates.log:
    ⬅️ CLICK data=«alw:buyq:a_s1:5:42» uid=42@amir(Amir) chat=100 | state=AllianceStates:buying_squads
    💥 خطا حینِ پردازش | ... 
  و در errors.log همان لحظه traceback کامل + همان متن می‌آید → بازتولیدِ باگ = خواندنِ
  چند خطِ متوالی. آپدیت‌های کندتر از ۳ ثانیه هم به‌صورتِ 🐢 در errors.log علامت می‌خورند.

  استفاده برای دیباگ:
    python3 log_healthcheck.py logs/errors.log --lines 300
  در کدِ خودت:
    from app.utils.logging_setup import get_logger
    log = get_logger(__name__)
    log.info("...")  /  log.exception("...")  # exception → traceback کامل در errors.log

  نصب: bot.py (setup_logging + میدل‌ور به‌عنوانِ بیرونی‌ترین لایه + dp.errors.register)
  و passenger_wsgi.py (setup_logging). بدونِ تغییر در هیچ هندلرِ دیگر.


■ ۳) آیکونِ Custom Emoji روی دکمه‌های شیشه‌ای — بررسیِ رسمی و پیاده‌سازی
  نتیجه‌ی بررسیِ Telegram Bot API (بدونِ حدس):
    • از Bot API 9.4 فیلدِ «icon_custom_emoji_id» به InlineKeyboardButton و
      KeyboardButton اضافه شده: «یک آیکونِ ایموجیِ پرمیوم قبل از متنِ دکمه».
    • متنِ دکمه‌ها MessageEntity نمی‌پذیرد؛ پس custom emoji «داخلِ متن» با
      offset/length برای دکمه وجود ندارد — راهِ رسمیِ دکمه فقط همین فیلد است
      (در هر دکمه یک آیکون، قبل از متن). متن می‌تواند ایموجیِ استاندارد هم داشته باشد.
    • شرطِ تلگرام: ربات باید مجاز به custom emoji باشد (یوزرنیمِ Fragment یا
      پرمیومِ مالک) — همان شرطی که ربات از v1.8.1.6 برای tg-emoji در پیام‌ها دارد.
    • برای «متنِ پیام» (نه دکمه) راهِ entity همچنان MessageEntity(type=custom_emoji)
      با offset/length بر حسب UTF-16 است → helper مخصوصش هم ساخته شد.

  سازگاری با aiogram==3.13.1 (نسخه‌ی پروژه، بدونِ ارتقای اجباری):
    • این نسخه قدیمی‌تر از Bot API 9.4 است و فیلد را «بومی» ندارد، اما تایپ‌های
      aiogram 3 در سازنده extra_data می‌پذیرند (extra="allow") و فیلدهای اضافه در
      سریالایزِ نهایی به تلگرام می‌رسند — این همان مسیرِ رسمیِ عبورِ فیلدهای تازه است.
    • ماژول هنگامِ ساختِ اولین دکمه این را «اجرایی» آزمون می‌کند (buttons_support_check)
      و نتیجه را در لاگ می‌نویسد؛ اگر روی هاست False شد یعنی aiogram باید ارتقا یابد.
    • شبکهٔ ایمنی: اگر تلگرام آیکون را رد کند، premium_emoji middleware به‌صورتِ
      خودکار آیکون‌ها را برمی‌دارد و همان پیام را سالم می‌فرستد (دکمه و callback سالم).

  فایلِ جدید: app/utils/emoji_buttons.py
    • emoji_button(text=..., callback_data=..., custom_emoji_id="...") → دکمه‌ی معتبر
    • نامِ مستعار: button(text="فروشگاه", custom_emoji_id="...") — همان سینتکسِ خواسته‌شده
    • emoji="🛒" → آیدی از نگاشتِ پکِ خودت (app/data/premium_emoji.py) خوانده می‌شود و
      ایموجیِ تکراری از ابتدای متن برداشته می‌شود تا دوبله نشود؛ اگر در پک نبود،
      دکمه بدونِ آیکون و با متنِ سالم ساخته می‌شود (منوها هرگز نمی‌شکنند).
    • EmojiKeyboardBuilder — جایگزینِ drop-in برای InlineKeyboardBuilder؛ بدونِ
      پارامترهای جدید دقیقاً رفتارِ قبلی (یعنی هیچ منوی فعلی‌ای تغییر نمی‌کند).
    • style="danger|success|primary" (Bot API 9.4) هم پشتیبانی می‌شود (اختیاری).
    • custom_emoji_entities(text) → برای متنِ پیام با offset/lengthِ درستِ UTF-16.
    • demo_keyboard(owner_id) → نمونه‌ی واقعیِ ۳ دکمه‌ای (🛒 فروشگاه/⚔️ نظامی/🏠 منو)
      با callback_dataهای واقعیِ ربات (mil:shop / mil:hub / menu:main).

  نمونه‌ی درونِ ربات: منوهای جدیدِ سربازخانه‌ی اتحادیه (alliance_menu.py) با
  EmojiKeyboardBuilder و آیکون‌های پکِ RestrictedEmoji ساخته شده‌اند.

  محدودیتِ رسمی (مهم): تلگرام در هر دکمه فقط «یک» آیکون و فقط «قبل از متن» می‌گذارد؛
  چند ایموجیِ پرمیومِ داخلِ متنِ دکمه در هیچ نسخه‌ی Bot API وجود ندارد. هر جا چنین
  چیزی دیدی، شبیه‌سازیِ غیررسمی است — ما همان قابلیتِ رسمی را پیاده کردیم.
